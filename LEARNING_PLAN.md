## Шаг 0. Разберись, как устроен ТВОЙ проект (1 вечер)

### Файлы проекта — что за что отвечает

| Файл | Что делает |

| `index.html` | Единственная HTML-страница. В `<div id="root">` React вживит всё приложение. Подключает `/src/main.jsx` |
| `src/main.jsx` | Точка входа: создаёт корень React и рендерит `<App />` внутри `<StrictMode>` |
| `src/App.jsx` | Главный компонент. Всё, что описывается функцией, возвращающей JSX, — это компонент React |
| `src/index.css` | Глобальные стили (CSS-переменные, шрифты, body) |
| `src/App.css` | Стили шаблона |
| `package.json` | Описание проекта и его зависимостей |
| `vite.config.js` | Настройки Vite (плагины, React Compiler, адрес dev-сервера) |
| `.oxlintrc.json` | Настройки линтера (проверка ошибок в коде) |

### `package.json` — «душа» проекта

- **`scripts`** — команды:
  - `npm run dev` — сервер разработки (мгновенное обновление HMR)
  - `npm run build` — собрать оптимизированную версию для продакшена
  - `npm run preview` — посмотреть собранную версию локально
  - `npm run lint` — проверить код линтером
- **`dependencies`** — то, что приложению нужно в работе: `react`, `react-dom`
- **`devDependencies`** — инструменты только для разработки: Vite, Oxlint, плагины

### Ключевая ментальная модель

> Браузер не понимает JSX. Vite — «сборщик»: берёт `main.jsx`, слепляет все импорты,
> превращает JSX в обычный JavaScript и отдаёт браузеру.
> `npm run dev` — мгновенная разработка (HMR).
> `npm run build` — создаёт папку `dist/` для хостинга.

### Крутая фишка твоего шаблона

В `vite.config.js` уже включён **React Compiler** — он автоматически оптимизирует
перерисовки. Это новейшая технология, её почти нигде нет в старых гайдах.
Именно из-за неё `useMemo` / `useCallback` тебе почти не понадобятся.

## Шаг 1. Основа React — руки, а не теория (неделя 1–2)

### Темы по порядку (по 30–60 минут в день)

1. **JSX** — почему пишут `className`, а не `class`; вставка переменных в `{фигурные скобки}`
2. **Компоненты и пропсы** — как передавать данные «вниз» по дереву
3. **Состояние и события** — `useState`, `onClick`, `onChange`
4. **Условный рендеринг** — `{cond ? <A/> : <B/>}`, `&&`
5. **Списки и key** — `.map()`, почему React требует ключ

### Мини-проекты (важнее всей теории вместе взятой)

| Проект | Что прокачает |
|---|---|
| Счётчик с кнопками +/− | `useState`, события |
| Todo-list (добавить / удалить / галочка) | списки, `key`, формы |
| Калькулятор | подъём состояния наверх |
| Викторина с вопросами | условный рендеринг |

### Правило RSF

> **R**аботает → **S**охраняется → **F**оттачивается.
> Сначала добейся работоспособности, потом рефактори. Смотри в консоль браузера
> (F12) — React пишет туда понятные ошибки.

## Шаг 2. Хуки — «магия», на которой всё стоит (неделя 3–4)

### Темы

1. **`useEffect`** — действия после рендера: загрузка данных, таймеры, подписки
2. **`useRef`** — ссылки на DOM + хранение значений без перерисовки
3. **`useMemo` / `useCallback`** — оптимизация (но у тебя React Compiler — смотришь вскользь!)
4. **Кастомные хуки** — выноси повторяющуюся логику в свои хуки (`useLocalStorage`, `useFetch`)
5. **Работа с API** — `fetch`, `async/await`, состояния загрузки/ошибки

### Мини-проекты

- Приложение погоды по геолокации (бесплатный API open-meteo — ключ не нужен)
- Кастомный хук `useLocalStorage` — чтобы todo-лист переживал перезагрузку
- Генератор цитат/картинок через публичный API с кнопкой «обновить»

## Шаг 3. Мультистраничность и состояние (неделя 5–6)

### Темы

1. **Роутинг** — `react-router-dom`: страницы `/`, `/about`, `/blog/:id`
2. **Поднятие состояния** — данные живут в родителе, передаются вниз
3. **Context API** — общее состояние без прокидывания пропсов через 10 компонентов
4. **Формы** — контролируемые input'ы, валидация
5. **Zustand** — самая простая библиотека состояния (лёгче Redux; для новичка Redux избыточен)

### Мини-проект

> Интернет-магазин: каталог с пагинацией (данные из JSON-файла), страница товара по id,
> корзина на Zustand.

## Шаг 4. Архитектура — как думает профессионал (неделя 7–8)

- Декомпозиция: компоненты как «лего» — маленькие, переиспользуемые (Кнопка, Карточка, Модалка)
- Файловая структура: `components/`, `hooks/`, `utils/`, `pages/`
- `props.children` и композиция
- Разделение на «умные» и «глупые» компоненты
- Удобные alias'ы импортов (`@/components/...`)

## Шаг 5. Продакшн и завершение (неделя 9–10)

### Темы

1. Переменные окружения: файл `.env` с `VITE_API_KEY=...` (на клиенте ничего секретного!)
2. `npm run build` → папка `dist/` → `npm run preview`
3. Деплой на **Vercel** (5 минут, бесплатно, автоматически подхватывает Vite)
4. Оптимизация размера бандла

## 🚨 Правила, которые уберегут от мусора

1. **Не учись по материалам старше 2 лет** — React развивается быстро
2. **У тебя уже React Compiler** — не гугли «useMemo оптимизация», он делает это сам
3. **Не ставь Redux и иконочные библиотеки на старте** — сначала руками
4. **Код каждый день**, даже 20 минут. Теория без практики забывается за неделю
5. **Читай и решай ошибки сам** — это 80% роста
